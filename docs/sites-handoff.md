# ChatGPT Sites 引き継ぎ

## 1. 完成している範囲と次の作業

このリポジトリは、承認済み仕様v0.4、動作する静的な探索・推薦デモ、テスト、ビルドとSites用の作成指示を提供する。**実データの共同学習ゲームは未接続**。サイトの見た目を作り直す前に、既存ファイルと仕様を読むこと。

採用済みの画面基準は `index.html` と `styles.css`。日本語、濃紺背景、カード型の候補一覧、推薦サイドパネル、検索・ID入力・理由入力を維持する。デモの仮想値を実測値に見せない。

## 2. プラットフォームの扱い

OpenAIの公式案内では、SitesはChatGPT Workで作成でき、ファイル・リンク等を材料として渡し、プレビュー後にデプロイしてURLを発行する。DBへの票の保存も用途として示されている。ただし、実際に使えるランタイム、認証、API、永続保存は作業環境で確認する。未確認のSites SDK名やGitHub自動同期機能を仮定しない。

参照（2026-11-15確認）：
- https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites
- https://developers.openai.com/training/walkthroughs/building-a-shareable-site

**Public GitHubリポジトリ＝公開サイトではない。** この引き継ぎ自体はサイトを作成・デプロイしない。新しいSitesではまず非公開プレビューを作り、一般公開は別途確認する。

## 3. 静的デモの持ち込み

Node.js 22以上で `npm run check`、`npm run build`。公開する静的ディレクトリは `dist/`。ビルドは明示したファイルだけをコピーし、秘密情報やデータセットを含めない。サーバー確認は `npm run preview` で行えるが、このNodeサーバーはローカル確認専用。

HTMLのES module、CSS、リンクが解決することを確認する。Sitesが別のエントリ形式を要求する場合のみラッパーを追加し、デモデータの出所表示、最大10件、ID入力の冪等性、空リスト保存を壊さないこと。

## 4. 本実装の責務分離

| 層 | 責務 | 現状 |
|---|---|---|
| ブラウザ | 探索、状態表示、推薦操作、結果表示 | デモのみ実装 |
| Sites側または対応バックエンド | 認証、票の永続化、締切・排他、公開情報のAPI | 未実装 |
| Python MLワーカー | CIFAR-10分割、CNN、2アーム学習、検証、成果物保存 | 未実装 |
| 非公開ストレージ | 重み、optimizer、内部検証、監査・乱数情報 | 未設定 |

SitesでPython/PyTorch/GPUの常駐処理が動くとは仮定しない。対応が確認できなければ、サイトは安全なサーバー側API経由で別ワーカーに接続する。学習をクリックごとに起動せず、締切後の1ジョブにまとめる。

## 5. サーバー実装の契約

詳細なパス・型・状態遷移は `spec-v0.4.md` 第6〜12節を正とする。

- 現在ラウンド、候補一覧（最大48件）、個別候補、本人の推薦、結果・履歴をAPIから取得。
- 利用者IDは検証済みセッションから導出する。クライアントの `user_id`、役割、締切時刻は信用しない。
- 推薦は同一ユーザー・同一ラウンド・同一候補で一意。重複PUTは票を増やさない。10件上限と締切を同一トランザクションで検査。
- 推薦理由は最大400文字のプレーンテキスト。HTMLとして挿入せず、公開履歴では個人のメモを公開しない。
- 認証失敗は401/403、締切・状態競合は409。送信失敗は未受付として残し、UIだけ成功させない。
- 公開監視の集計情報だけを公開し、内部安全検証・テスト画像のIDやラベルは配信しない。
- モデル更新と候補スコアはcheckpoint IDを対応付け、古いLossを現在のLossとして表示しない。
- サイトの閲覧権限とアプリの投票者・管理者権限を別途確認する。匿名閲覧が可能でも匿名の管理者操作は禁止。

## 6. 実学習の接続順序

P0：固定分割と初期CNN、checkpoint＋SGD momentumの保存、公開・内部検証の評価。

P1：同一状態からCommunity/Randomを分岐し、各128画像、batch32、10epoch、40更新ステップ。画像の選択seed・学習seed・コード版・実行環境を保存。学習率は0.01固定の暫定仕様。

P2：Sitesのサーバー推薦と候補APIを接続。画像権利の確認が済むまで一般公開の画像配信は無効。

P3：締切スナップショット、ジョブ状態、再試行、二重実行防止、原子的な昇格、次ラウンドを接続。Communityの勝敗と昇格の採否を別に表示。

P4：実データで仕様AC-01〜18を検証する。1ラウンド成功だけで人間投票の研究上の優位を主張しない。

## 7. 公開前ゲート

認証・権限、締切、重複票、11件目拒否、サーバー障害時の表示、実画像公開権利、秘密情報の非公開、スマートフォン・キーボード操作、ロールバックを検査する。公開範囲を確認するまでは非公開プレビューを維持。画像権利が未確認でも、画像を含まないデモのプレビューは作成できる。

## 8. 引き継ぎ時に報告すること

実際に発行されたURL、デプロイしたソース版、テスト結果、実装／未実装の区別、利用者ごとのレコード分離、MLワーカー接続の有無を報告する。URL、数値、成功状態を作り上げない。
