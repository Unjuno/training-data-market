# Training Data Market — Game loop / experience v1.1

## Why
The current product offers image selection but little feedback about the participant's judgment. A first-time player needs one comprehensible objective and a reason to return when a round concludes.

## Confirmed constraints
- One shared model, community-selected training samples, random-control arm, fixed training budget.
- Server decides deadline and winner; client never triggers training.
- Real-money betting, individual causal-contribution claims, publishing holdout data, and synthetic-data masquerading as CIFAR-10 are out of scope.
- ChatGPT Sites is the planned web surface, but a separate CPU/GPU worker trains PyTorch. Local mode remains runnable independently.

## Approaches considered
1. Cosmetic gamification only — badges and animation; insufficient falsifiable gameplay.
2. Individual sample rewards — falsely attributes a batch's improvement to individual images; rejected.
3. **Calibrated forecast + scouting quest** — recommended. Players pick images and independently predict whether the community arm will outperform random; reward forecast calibration, not spurious sample attribution.

## Game flow
1. OBSERVE — display pairwise weakness (two classes), validation recall, loss and sample observations; these are measurements, not projected success.
2. SCOUT — search candidate images and vote for up to ten. The backend persists each choice instantly. Provide direct target-class and wrong-prediction shortcuts.
3. FORECAST — choose a 5–95% probability, in 5% steps, that *Community will achieve lower target-class validation cross-entropy than Random* this round. One forecast per pseudonymous browser identity, mutable before the authoritative deadline.
4. LOCK — votes and forecasts close together. No more edits, regardless of delayed worker execution.
5. REVEAL — side-by-side actual public validation metrics, which model was promoted and why. Score the forecast independently of promotion selection and never score when there are zero community picks, no valid measurements or a tie within 0.001 target-loss.
6. RETURN — personal round history, total forecast points (0–100 per scored round), previous result, new quest.

### Scoring
Binary outcome y=1 when community target_loss + 0.001 < random target_loss; y=0 when reverse. Other conditions (tie, insufficient votes, malformed metrics) yield no scored outcome. Forecast probability q is a decimal 0.05–0.95. Individual points = round(100 * [1 - (q-y)^2]); this quadratic/Brier complement is strictly proper before rounding. Random chance q=0.5 yields 75/100, disclose this explicitly; scores are not proof of skill until compared against a 50% baseline across independent rounds. No cash, transfers, sale or reward linkage to model updates.

## Success / UX acceptance (design hypotheses)
- A new player can name the objective and independently place at least one recommendation and a forecast.
- Input and saved state are unambiguous; errors are recoverable without deleting votes.
- Mobile (390px) preserves accessible controls, no horizontal scrolling, primary actions >=44px.
- No fictitious improvement, no rank-as-causation, no non-authenticated identity marketed as verified account.
- Target metric and baseline are disclosed before the choice.

## Architecture
- `backend/forecast.py` contains pure settlement and score calculation (no DB).
- `backend/store.py` persists forecasts and computes personal scored history from immutable published rounds.
- `backend/service.py` provides authenticated-by-signed-cookie `PUT/GET .../forecast/me` and `GET .../me/game-stats` using the existing same-origin layer.
- `src/game-view.js` defines pure view models for quest state and forecast cards; `live.js` wires interactions.
- `game.css` styles only game-specific components; existing visual language remains.

## Deferred
Leaderboard across unverified browser identities, achievement economy, real-money points, changing learning rate, marketing/SEO, cloud GPU deployment, and public Sites release. These require separate security/product decisions.
