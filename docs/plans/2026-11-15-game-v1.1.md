# Forecast Quest Implementation Plan

**Goal:** Make selection and prediction a complete, testable player loop without compromising experimental fairness.

**Spec:** `docs/design/2026-11-15-game-loop.md`

**Tech:** Python 3.11+/FastAPI/SQLite/PyTorch; native JS modules; Chromium for local rendering and interaction checks.

## Tasks
- [x] Backend scoring: pure proper-score implementation, tie/no-vote rules and unit tests (red/green).
- [x] Persistence: SQLite forecast migration, deadline guard, personal history with race/idempotency tests.
- [x] API: forecast submission/read/statistics routes, signed-session independence and invalid input tests.
- [x] UI: mission guidance, user strategy shortcuts, forecast form, result settlement, personal history; tests for formatting and interaction.
- [x] Mobile/desktop design: dedicated CSS, responsive layout, accessibility and no misleading claims.
- [x] E2E: two-browser voting, forecasts, closed-round rejection, actual 40-step training, reveal and score; HTML rendering checks with Chromium 144; static bundle tests.
- [x] Publish feature branch and open pull request; state what is not tested (native Chrome, Sites/real CIFAR-10).
